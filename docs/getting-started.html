Getting Started

Install, configure, port, and run.

1. Install

git submodule add https://github.com/hedgetechllc/nandlog.git external/nandlog

There is no build system and nothing to install. Add three source files to your build:

FileNotes
nandlog.cAlways.
chips/nandlog_chip_<PART>.cExactly one, for the part you have fitted.
your nandlog_port.cCopy the template from the repository root and fill in the stubs.

Put the repository root and chips/ on the include path.

Build with -fno-strict-aliasing. This is required, not advisory. The log reads page and metadata headers out of byte buffers by pointer cast, which an optimiser is otherwise entitled to reason around. It costs nothing measurable. -O2 is otherwise fine and worth having.

2. Configure

Edit nandlog_conf.h. Nothing is derived and nothing has a silent default — anything missing is a named compile error.

SettingDefaultMeaning
NANDLOG_HAS_HARDWARE1Set to 0 to compile the library to no-op stand-ins that accept everything and return nothing, so the application above needs no conditionals of its own.
NANDLOG_MAX_PAGE_SIZE_BYTES4096The largest page you are prepared to spend RAM on. Every buffer is sized from this.
NANDLOG_MAX_SPARE_SIZE_BYTES256The same for the spare area.
NANDLOG_BLOCK_ERRORS_BEFORE_REMOVAL3Program or erase attempts on one block before it is retired.
NANDLOG_ERASE_AHEAD_BLOCKS2Blocks kept erased ahead of the write head, so a page write never waits on an erase.
NANDLOG_PAGE_PLACEMENT_ATTEMPTS3Blocks a single page write may relocate through before the log concludes the part will not hold it.
NANDLOG_MAX_EPOCH_DETAILS_BYTES512Largest caller-defined blob stored with each epoch.
NANDLOG_TIMESTAMP_TOLERANCE_MS250How far a timestamp may step backwards before the log treats it as the time base having moved rather than two writers disagreeing.
NANDLOG_RECORD_FRAMING1Whether each record carries its own length, so a reader can walk a page without knowing your record types.
NANDLOG_BUSY_POLL_INTERVAL_US10How often to poll the part's BUSY bit.
NANDLOG_BUSY_TIMEOUT_MS500How long to poll before declaring the part dead.
NANDLOG_CHIP_PAGE_COPY1Whether a relocated page may be moved inside the chip instead of across the bus.

Setting the two MAX_ values larger than your part needs costs only unused RAM. A part whose page exceeds the budget is a compile error inside that part's driver.

3. Port

Copy nandlog_port.c from the repository root into your own tree, delete its #error line, and implement thirteen functions. Each stub documents what the layer above assumes of it. See Porting for the detail and a complete worked example.

4. Bring the log up

#include "nandlog.h"

if (!nandlog_init())
{
   /* No part fitted, or the port would not open. No other call should be made. */
   return;
}

nandlog_init() opens the port, identifies the part, loads its bad-block table, recovers the current epoch and locates the write head. It is safe to call more than once. nandlog_probe() is the cheaper question for a build that only wants to know whether a part is present.

5. Start an epoch

An epoch is one generation of the log, with its own sequence numbering from zero. Reads cover one epoch at a time. Starting a new one makes everything logged previously unreachable through the API, though it stays on the part until the write head sweeps over it.

nandlog_begin_session();
nandlog_begin_epoch(&experiment_details, sizeof(experiment_details));
nandlog_end_session();

A session holds the part powered across a run of operations instead of waking and sleeping it around each one. Epoch operations and reads require one; ordinary logging does not. Sessions do not nest.

The details blob is opaque — the log stores it, checksums it, and hands it back, but never looks inside.

6. Log records

nandlog_store_record(RECORD_SAMPLE, milliseconds, &sample, sizeof(sample));

record_type and the data are opaque. The timestamp is only ever compared, never interpreted, so its epoch and units are yours.

This call is cheap but not free every time: a page is committed as soon as the next record will not fit, so it occasionally writes to flash. Records are never split across pages, and one larger than a page is dropped rather than corrupting the stream. nandlog_data_bytes_per_page() is how much a page holds on the fitted part.

A partial page only reaches flash when you ask for it:

nandlog_flush(true);                       /* commit whatever is buffered  */
if (nandlog_has_buffered_data()) { ... }   /* anything unwritten in RAM?   */

Call nandlog_flush(true) on a timer and at shutdown. Without it, up to one page of recent records sits in RAM and is lost to an unexpected reboot.

7. Read it back

uint8_t page[NANDLOG_MAX_DATA_BYTES_PER_PAGE];
uint32_t num_pages = 0, num_bytes = 0;

nandlog_begin_session();
nandlog_begin_reading(start_ms, end_ms);     /* 0 for either bound means "no bound" */
nandlog_read_span(&num_pages, &num_bytes);

for (uint32_t i = 0; i < num_pages; ++i)
{
   nandlog_page_header_t header;
   const uint32_t length = nandlog_retrieve_next_page(page, &header);
   if (length == 0)
   {
      /* Unreadable page. This is a gap, not the end of the read:
         header.seq still identifies which page it was. */
   }
}

nandlog_end_reading();
nandlog_end_session();                       /* also ends any open read */

Writing is refused while a read is open. Both time bounds are resolved inside nandlog_begin_reading(), and both err outward — a little extra data for you to filter, rather than dropping data that was asked for.

nandlog_read_span() costs a read of every page in the span when you ask for an exact byte total. That doubles the flash traffic of a download. Pass NULL for num_bytes unless you need the figure exactly — the page count alone is arithmetic and free.

Walking the records in a page

With NANDLOG_RECORD_FRAMING on, a payload can be walked without knowing your record types:

uint32_t offset = 0, record_bytes = 0;
const uint8_t *record = NULL;

while (nandlog_framed_next_record(payload, length, &offset, &record, &record_bytes))
{
   const uint8_t  type = record[0];
   uint32_t timestamp;  memcpy(&timestamp, record + 1, sizeof(timestamp));
   const uint8_t *data = record + 5;
   const uint32_t data_length = record_bytes - 5;
}

8. Check your work

Dump an image from the device and run it through the reference parser, which verifies every CRC independently of the device that wrote it:

./tools/nandlog_parse.py image  dump.bin --page-size 4096 --spare-size 256
./tools/nandlog_parse.py stream offload.bin --json

And run the host test suite, which exercises the real log and chip driver against an emulated part:

cd sim && make
