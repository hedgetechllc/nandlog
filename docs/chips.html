Chip Drivers

One .c file per part. Twelve functions.

Two drivers are supplied and each is complete on its own — nandlog_chip_common.h holds no command codes, no register numbers and no bit patterns, and there is no shared implementation beneath it. Copy whichever is closer to your part and work from the datasheet.

1. Declare the geometry

Six macros, then the common header. Geometry lives in the driver and nowhere else — not in a board header, not in the configuration file.

/* chips/nandlog_chip_MYPART.c */

#define NANDLOG_CHIP_NAME                    "MYPART"
#define NANDLOG_CHIP_PAGE_SIZE_BYTES         4096   /* main array, excluding spare  */
#define NANDLOG_CHIP_SPARE_SIZE_BYTES        256    /* spare/ECC bytes that follow  */
#define NANDLOG_CHIP_PAGES_PER_BLOCK         64     /* MUST be a power of two       */
#define NANDLOG_CHIP_BLOCK_COUNT             4096
#define NANDLOG_CHIP_RESERVED_BLOCKS         80     /* held back for bad blocks     */

#include "nandlog_chip_common.h"

The common header checks the set is complete, asserts the page fits NANDLOG_MAX_PAGE_SIZE_BYTES, and derives the addressing that follows:

DerivedValue
NANDLOG_CHIP_PAGE_COUNTpages in the whole array
NANDLOG_CHIP_PAGE_WITH_SPARE_SIZE_BYTESpage + spare
NANDLOG_CHIP_BLOCK_MASKmask a page address to its block
NANDLOG_CHIP_RESERVED_BASE_PAGEfirst page of the reserve
NANDLOG_BUSY_TIMEOUT_POLLSpoll count from the configured timeout
NANDLOG_CHIP_GEOMETRY_INITIALIZERfills a nandlog_geometry_t

How many blocks to reserve is a judgement call. It must cover the factory bad blocks (typically up to 2% of the array) plus whatever the part accumulates in service, plus somewhere to persist a bad-block table if your part has no hardware remapping. The supplied drivers reserve 80 of 4096 and 40 of 1024.

2. Implement twelve functions

Power contract. Every function below that touches the bus may assume the port is awake and the part is out of its low-power state. The log core guarantees that — it wakes both around each operation and puts them back afterwards, or holds them awake for the length of a session.

The corollary matters when you write a bench test for your driver: nandlog_init() deliberately leaves both asleep when it returns, so code that calls these functions directly must open a session first. On a peripheral that is merely unclocked rather than absent, the failure is a bus fault, not an error return. nandlog_chip_geometry() and nandlog_chip_is_bad_block() are the exceptions: both answer from RAM.

Identity and setup

const nandlog_geometry_t *nandlog_chip_geometry(void);

Return the geometry. Valid at any time, including before nandlog_chip_init(), because these are properties of the silicon rather than of its state.

const nandlog_geometry_t *nandlog_chip_geometry(void)
{
   static const nandlog_geometry_t geometry = NANDLOG_CHIP_GEOMETRY_INITIALIZER;
   return &geometry;
}
bool nandlog_chip_probe(void);

Confirm the part is present and answering, typically by reading its device ID and retrying for a bounded time. Safe to call before nandlog_chip_init().

void nandlog_chip_init(void);

Configure the part's status registers, then load the persisted bad-block table or, on a first boot, build one from the factory markers and persist it. Called once, after a successful probe.

void nandlog_chip_low_power(bool sleep);

Enter or leave the part's lowest-power state. May be empty if the part has no deep-power-down command worth the wake-up latency.

Data

bool nandlog_chip_read_page(uint8_t *buffer, uint32_t page);

Read a whole page. Returns false if the read reported an uncorrectable ECC error and the buffer is untrustworthy.

bool nandlog_chip_read_page_region(uint8_t *buffer, uint32_t page,
                                   uint32_t offset, uint32_t length);

Read length bytes starting at offset within the page. Same return meaning.

This one carries the most weight. The log reads far more 32-byte headers than whole pages, and a driver that implements this as "read the whole page and copy a slice" throws away the entire saving. It must issue the part's column address. On a full epoch of a 4 KB-page part that is the difference between 8 MB and 1 GB of bus traffic for a single bounded download.

Reading less than a page is safe on any part with on-die ECC: correction happens when the page is latched into the cache register, so the error status is settled before a byte is clocked out and cannot depend on how much of that register the host then looks at.

static bool read_page_region(uint8_t *buffer, uint32_t page, uint32_t column, uint32_t length)
{
   /* 16-bit column address, most significant byte first, then a dummy byte */
   const uint8_t column_address[3] = { (uint8_t)(column >> 8), (uint8_t)column, 0x00 };
   uint8_t page_address[3];
   split_page_address(page, page_address);

   wait_until_not_busy();
   nandlog_port_transfer_write(COMMAND_PAGE_DATA_READ, NULL, 0, page_address, sizeof(page_address));
   wait_until_not_busy();
   nandlog_port_transfer_read(COMMAND_READ, column_address, sizeof(column_address), buffer, length);
   wait_until_not_busy();
   return (read_register(STATUS_REGISTER_3) & STATUS_PAGE_FATAL_ERROR) != STATUS_PAGE_FATAL_ERROR;
}
bool nandlog_chip_write_page(const uint8_t *data, uint32_t page);

Program a whole page, retrying up to NANDLOG_BLOCK_ERRORS_BEFORE_REMOVAL times. Returns false if the part reported a program failure every time. Whether the block is then retired is the caller's decision. Open and close write protection for yourself.

bool nandlog_chip_erase_block(uint32_t page);

Erase the block containing page. False means the part reported an erase failure.

nandlog_copy_result_t nandlog_chip_copy_page(uint32_t source_page, uint32_t destination_page);

Relocate one page to another inside the chip. Most SPI NAND can latch a page into its own cache register and program it straight back out to a different address, so a page that is only being moved never crosses the bus — on a 4 KB part that is 8 KB of traffic saved per relocated page.

Return one of:

ValueMeaning
NANDLOG_COPY_OKThe part did it.
NANDLOG_COPY_FAILEDThe part tried and reported a program failure, so the destination block is suspect.
NANDLOG_COPY_UNSUPPORTEDNo such command. The caller falls back to a read and a write.

A part with no internal data-move command expands a macro instead of writing this out:

NANDLOG_CHIP_NO_INTERNAL_PAGE_COPY

The implementation is a page read followed by a program execute, with no program data load between them — that is the whole point:

wait_until_not_busy();
nandlog_port_transfer_write(COMMAND_PAGE_DATA_READ, NULL, 0, source_address, 3);
wait_until_not_busy();
nandlog_port_transfer_write(COMMAND_WRITE_ENABLE, NULL, 0, NULL, 0);
nandlog_port_transfer_write(COMMAND_PROGRAM_EXECUTE, NULL, 0, destination_address, 3);
wait_until_not_busy();

An uncorrectable source page is not a failure here. Its uncorrected bytes are what lands at the destination, which reads back with sound ECC and a payload CRC that will not match — a gap, which is exactly what reading it into RAM and finding it unreadable would have produced.

Bad blocks

bool nandlog_chip_is_bad_block(uint32_t page);

Whether the block containing page is known bad.

This must not touch flash. The log calls it once per page on the write path and once per page in the epoch when a bounded download opens. Answer from a table or bitmap in RAM, built during nandlog_chip_init().

void nandlog_chip_mark_bad_block(uint32_t page);

Retire the block. Make this idempotent — retiring a block that is already retired must not consume a second table slot or a second spare block.

bool nandlog_chip_reset_bad_blocks(void);

Recovery utility. Discard the persisted table so it is rebuilt on the next boot. Return whether the table was verified gone afterwards, rather than assuming the erase took. A part that remaps in hardware cannot forget; say so through nandlog_port_log() and return true.

3. Two strategies for bad blocks

The supplied drivers take opposite approaches, which is the point of putting this behind the chip seam.

Software tableHardware LUT
ExampleAS5F18G04SNDW25N01GWZEIG
Where it livesA marker page in the reserve, mirrored in RAMThe chip's own 20-entry remapping table
First bootScan every block's spare-area marker, build the table, persist itRead the chip's LUT; scan for factory markers once
Later bootsFind and load the marker pageRead the chip's LUT
ResetErase the reserve, verify no marker survivesNot possible — entries are one-way

4. Test it

Point the host simulator at your driver by editing the SRC line in sim/Makefile, then:

cd sim && make

The simulator emulates a NAND part at the SPI command level, so your driver runs on it unmodified — addressing, status-register handshakes, busy-waiting and bad-block bookkeeping are all exercised. It builds the emulated part from whatever geometry your driver reports, so the two cannot disagree.

Then run the three on-device tests. Those cover what the simulator cannot: whether your column addressing is right on real silicon, whether the internal copy behaves, and what the part's on-die ECC does to the spare area.

A wrong column byte order fails open. It reads 0xFF from the wrong place, the factory bad-block scan concludes every block is good, and nothing is retired. The host simulator cannot catch this, because it decodes the column address the same way your driver encodes it. Run the on-device read test before deploying.
