Porting

Thirteen functions, and a fourteenth if the log's CRC goes to hardware. One file. This is the only code you write.

Copy nandlog_port.c from the repository root into your own tree, delete its #error line, and fill in the stubs. Everything above this file is platform-independent.

The interface

FunctionResponsibility
nandlog_port_initConfigure the SPI peripheral and its pins; drive write-protect and hold to their inactive state. Return false to prevent the log coming up at all.
nandlog_port_deinitRelease the peripheral, leaving it in a state init can start from again.
nandlog_port_transfer_readOne command byte, n address bytes, then clock data back — as one exchange the part sees as uninterrupted.
nandlog_port_transfer_writeThe same in the other direction.
nandlog_port_lock / _unlockSerialise the library against itself.
nandlog_port_write_enableGate the part's write-protect pin: true permits programming and erasing.
nandlog_port_powerWake the peripheral or return it to its lowest-power state.
nandlog_port_logprintf-style sink for the library's diagnostics; NANDLOG_LOG_LEVEL sets which reach it.
nandlog_port_delay_usBusy-wait. Called often, to pace the BUSY poll; must be cheap and must not yield.
nandlog_port_delay_msCoarse delay, used only while waiting for a part to come up. Yielding is fine.
nandlog_port_fatalThe part stopped answering. Must not return, and is declared so.
nandlog_port_unwritableThe part answers, but the log stopped taking records: no block will retain a page, or the epoch was sealed.
nandlog_port_crc32Optional, only with NANDLOG_PORT_CRC32 set: the log's CRC-32, computed however the host likes, returning exactly what zlib.crc32(data, crc) would. Below.
nandlog_port_crc32_hardwareOptional, and never called by the library: whether nandlog_port_crc32() is running on hardware. The on-device benchmark reports it.

Four things worth getting right

The transfer shape is command, address, data

Both transfer functions take (command, address, address_length, buffer, length). The command byte and address bytes go out first, then the data, with chip-select asserted across the whole exchange.

  • address may be NULL with address_length zero.
  • length may be zero, and that transfer must still be issued — a part can require the empty transaction to complete the command.
  • length may exceed a whole page. If your peripheral has a maximum transaction size, split across as many transactions as needed, keeping chip-select asserted between them.
  • There is no error return. A transfer either completes or does not return, so a failure that cannot be retried has to end in nandlog_port_fatal().

Nothing above this file names a bus. The shape is what NAND speaks whether it is wired to SPI in one, two, four or eight lanes, or to a parallel ONFI bus with a port that drives the command and address latches.

The lock protects a shared cache register, not just a buffer

A single-threaded system can leave both lock functions empty. Anything else must supply a real mutex. Reading a page is a sequence of commands against the one cache register inside the part — latch the page, then clock it out. Two callers interleaving those sequences read each other's pages, and nothing about the bus traffic looks wrong.

Every public function takes the lock for its whole duration and does its work in an internal, so a caller never holds it and these never nest. If the lock cannot be taken in every context you call from — before the scheduler starts, or from an interrupt — detect that case and skip the lock rather than blocking or failing. It is one lock for everything, so a call that only buffers a record can wait behind a long one: a bounded nandlog_begin_reading() or a byte-exact nandlog_read_span() is a pass over the whole epoch, which on a full epoch of the Alliance part takes minutes. A task that logs on a deadline should not share the log with an open download, or should buffer its records itself while one runs.

Write-protect polarity is a board property

Most WP# pins are active low, but a board may invert one. Get this backwards and every program silently fails.

The two failure callbacks are not the same

nandlog_port_fatal() is called when the part stops answering at all — BUSY never cleared, or a transfer failed past retrying. A library has no business resetting the system it is embedded in, so what happens next is yours — but it must not return. The header declares it with NANDLOG_NORETURN (the GCC/Clang attribute, or C11's _Noreturn), and the drivers treat everything after the call as unreachable. Reset, halt, or longjmp out to a point that stops calling the log. Should a port return anyway, the status the timed-out wait hands back fails every check its caller makes, so it can never be read as success.

nandlog_port_unwritable() is the softer failure: the part still answers, but no block will retain a page, or a block could not be retired persistently — the log stops taking records until a reboot or a new epoch — or a boot sealed the epoch, because its list of passed-over positions is nearly full, its newest metadata slot no longer reads whole, or the bad-block table no longer lays it out as it was written; then nandlog_store_record() returns NANDLOG_ERR_SEALED at every boot until a new epoch is begun. Nothing here is urgent and nothing here should reset the system — it is still running, it just has nowhere to put data. Leave a breadcrumb the next boot can find, or tell whoever can begin a new epoch.

Optional: the log's CRC on a hardware engine

Every page the log writes carries two CRC-32s, one over its header and one over its payload, and every page it reads is checked against both. In software that is the library's own table-driven loop, which on a Cortex-M4 at 96 MHz costs a few hundred microseconds per 4 KB page (see Performance). A host with a CRC engine can take it over: set NANDLOG_PORT_CRC32 to 1 and implement nandlog_port_crc32(), and every CRC the log writes or checks comes from there. The contract, in full:

  • Return exactly what zlib.crc32(data, crc) returns: the reflected IEEE 802.3 CRC-32 (polynomial 0xEDB88320, initial value and final XOR 0xFFFFFFFF) of the bytes crc was returned for, followed by these length bytes. So 0 begins a value, length 0 returns crc as it is, "123456789" from 0 gives 0xCBF43926, and the CRC of a then b is nandlog_port_crc32(nandlog_port_crc32(0, a, n), b, m). The log relies on that continuation: it adds each record to its page's CRC as the record is stored, so the commit computes only the header's.
  • The library promises nothing about data but that it can be read: any alignment, any length from 0 (when it may be NULL) to a page, in RAM or in constant data. An engine with rules of its own — word-aligned addresses, lengths a multiple of four — does the bytes it can and hands the rest to nandlog_crc32_software(), the library's software CRC under the same contract, which continues the same value.
  • Calls come with the library's lock held, and from nandlog_init() only after nandlog_port_init() has returned true; nandlog_crc32() calls it from whatever context calls that. An engine other drivers use too has to be shared: leave it alone while another user's run is going, keep other tasks off it during a run, and put back any register you borrowed.
  • Short runs are common: 28-byte headers, and every record as it is stored. A run too short to repay the engine's setup is cheaper in software.

A wrong CRC is written to the part as it is. The commit's read-back compares the page with what was meant to be written, CRC included, so nothing in the log can tell; the page then fails its check at every read and is served as a gap. An engine whose conventions are not documented — bit order, whether its result is read before or after the final XOR, what continuing a run means — has to agree with nandlog_crc32_software() on known vectors, including a continuation split at an odd offset, before its first use, and be left alone for good if it ever disagrees.

The template in nandlog_port.c carries a commented sketch; the worked example below is a complete one.

Worked example: Ambiq Apollo4 under FreeRTOS

A complete port, using the Ambiq HAL's IOM peripheral. The pin names, the print() sink and the system_* calls belong to the surrounding firmware, not to nandlog.

Initialisation

#include "nandlog_port.h"
#include "logging.h"      /* the firmware's print() sink                        */
#include "system.h"       /* PIN_STORAGE_*, system_reset(), diagnostics         */

static void *spi_handle;
static SemaphoreHandle_t log_mutex;
static StaticSemaphore_t log_mutex_buffer;

bool nandlog_port_init(void)
{
   const am_hal_iom_config_t spi_config = {
      .eInterfaceMode = AM_HAL_IOM_SPI_MODE,
      .ui32ClockFreq  = AM_HAL_IOM_48MHZ,
      .eSpiMode       = AM_HAL_IOM_SPI_MODE_0
   };

   /* Configure and assert the write-protect and hold pins to disable them */
   am_hal_gpio_pinconfig(PIN_STORAGE_WRITE_PROTECT, am_hal_gpio_pincfg_output);
   am_hal_gpio_output_set(PIN_STORAGE_WRITE_PROTECT);
   am_hal_gpio_pinconfig(PIN_STORAGE_HOLD, am_hal_gpio_pincfg_output);
   am_hal_gpio_output_set(PIN_STORAGE_HOLD);

   /* Bring up the SPI module and its four pins */
   am_hal_iom_initialize(STORAGE_SPI_NUMBER, &spi_handle);
   am_hal_gpio_pinconfig(PIN_STORAGE_SPI_SCK,  sck_config);
   am_hal_gpio_pinconfig(PIN_STORAGE_SPI_MISO, miso_config);
   am_hal_gpio_pinconfig(PIN_STORAGE_SPI_MOSI, mosi_config);
   am_hal_gpio_pinconfig(PIN_STORAGE_SPI_CS,   cs_config);
   am_hal_iom_power_ctrl(spi_handle, AM_HAL_SYSCTRL_WAKE, false);
   am_hal_iom_configure(spi_handle, &spi_config);
   am_hal_iom_enable(spi_handle);
   return true;
}

void nandlog_port_deinit(void)
{
   am_hal_iom_disable(spi_handle);
   am_hal_iom_uninitialize(spi_handle);
   spi_handle = NULL;
}

Transfers

The command and address go out as one transaction with bContinue set, so chip-select stays asserted; the data then follows, split across as many transactions as the peripheral's maximum allows. The transaction count is fixed before the loop rather than tested against the remaining length, so a zero-length read still issues the single empty transaction that smaller-page parts rely on.

void nandlog_port_transfer_read(uint8_t command, const void *address, uint32_t address_length,
                                void *read_buffer, uint32_t read_length)
{
   uint32_t instruction = command, retries_remaining = 4;
   uint32_t num_reads = 1 + (read_length / (1 + AM_HAL_IOM_MAX_TXNSIZE_SPI));
   memcpy(((uint8_t*)&instruction) + 1, address, address_length);
   am_hal_iom_transfer_t spi_transaction = {
      .eDirection    = AM_HAL_IOM_TX,
      .ui32NumBytes  = 1 + address_length,
      .pui32TxBuffer = &instruction,
      .bContinue     = true,
      .ui8Priority   = 1
   };

   /* A transfer either completes or does not return */
   while (--retries_remaining &&
          (am_hal_iom_blocking_transfer(spi_handle, &spi_transaction) != AM_HAL_STATUS_SUCCESS))
      am_hal_delay_us(10);
   if (!retries_remaining)
      system_reset(true);

   uint32_t read_offset = 0;
   while (num_reads--)
   {
      uint32_t read_bytes = (read_length > AM_HAL_IOM_MAX_TXNSIZE_SPI)
                          ? AM_HAL_IOM_MAX_TXNSIZE_SPI : read_length;
      read_length -= read_bytes;

      retries_remaining = 4;
      spi_transaction.eDirection    = AM_HAL_IOM_RX;
      spi_transaction.ui32NumBytes  = read_bytes;
      spi_transaction.pui32TxBuffer = NULL;
      spi_transaction.pui32RxBuffer = (uint32_t*)((uint8_t*)read_buffer + read_offset);
      spi_transaction.bContinue     = read_length > 0;
      read_offset += read_bytes;

      while (--retries_remaining &&
             (am_hal_iom_blocking_transfer(spi_handle, &spi_transaction) != AM_HAL_STATUS_SUCCESS))
         am_hal_delay_us(10);
      if (!retries_remaining)
         system_reset(true);
   }
}

/* nandlog_port_transfer_write() is this function with the directions reversed,
   and splits its payload the same way for the same reason. */

Locking

Before the scheduler runs there is exactly one context, so there is nothing to serialise against — and taking a FreeRTOS mutex there, or from an interrupt, is an error rather than a wait. The mutex is created on first use, which is guaranteed to be after the scheduler has started, and the double check under a critical section makes the creation itself safe against two tasks arriving together.

static inline bool locking_applies(void)
{
   return (xTaskGetSchedulerState() == taskSCHEDULER_RUNNING) && !xPortIsInsideInterrupt();
}

void nandlog_port_lock(void)
{
   if (locking_applies())
   {
      if (!log_mutex)
      {
         taskENTER_CRITICAL();
         if (!log_mutex)
            log_mutex = xSemaphoreCreateMutexStatic(&log_mutex_buffer);
         taskEXIT_CRITICAL();
      }
      if (log_mutex)
         xSemaphoreTake(log_mutex, portMAX_DELAY);
   }
}

void nandlog_port_unlock(void)
{
   if (log_mutex && locking_applies())
      xSemaphoreGive(log_mutex);
}

The rest

On this board the write-protect pin is asserted high to permit programming.

void nandlog_port_write_enable(bool enable)
{
   if (enable)
      am_hal_gpio_output_set(PIN_STORAGE_WRITE_PROTECT);
   else
      am_hal_gpio_output_clear(PIN_STORAGE_WRITE_PROTECT);
}

void nandlog_port_power(bool awake)
{
   am_hal_iom_power_ctrl(spi_handle, awake ? AM_HAL_SYSCTRL_WAKE : AM_HAL_SYSCTRL_DEEPSLEEP, true);
}

void nandlog_port_delay_us(uint32_t microseconds) { am_hal_delay_us(microseconds); }
void nandlog_port_delay_ms(uint32_t milliseconds) { am_util_delay_ms(milliseconds); }

void nandlog_port_log(const char *format, ...)
{
   char message[160];
   va_list args;
   va_start(args, format);
   vsnprintf(message, sizeof(message), format, args);
   va_end(args);
   print("%s", message);
}

NANDLOG_NORETURN void nandlog_port_fatal(const char *reason)
{
   print("ERROR: Storage hardware fault: %s; resetting\n", reason);
   system_record_diagnostic(RESET_DIAGNOSTIC_STORAGE_FATAL);
   system_reset(true);
   for (;;)
      ;                    /* not reached; the reset does not return either */
}

void nandlog_port_unwritable(void)
{
   /* Not a reason to reset: the device still works, it just has nowhere to put data.
      Leave a breadcrumb so the next boot's log says the flash has already given up. */
   system_record_diagnostic(RESET_DIAGNOSTIC_STORAGE_UNWRITABLE);
}

The CRC engine

The Apollo4's security block computes CRC-32 in hardware (the HAL's am_hal_crc32()): it reads LEN bytes, a multiple of four, from SRCADDR, and goes on from the seed in RESULT. RESULT reads as the finished CRC, zlib's value, but a seed written to it is taken bit-reversed: a run that continues the zlib value z is seeded with __RBIT(~z). The HAL only ever seeds 0xFFFFFFFF, which bit reversal leaves alone. Ambiq documents neither; both were measured on an Apollo4 Plus. A wrong CRC would make its page read as damaged, so the port checks the engine at its first nandlog_port_init(): its CRC of "12345678" must be zlib's, and then the engine's whole path — software to the first word boundary, the engine for the whole words, software for the tail — must agree with nandlog_crc32_software() on "123456789" at every alignment, on 4,064 bytes of the program image whole and continued from a split at an odd offset, and on runs in RAM at every alignment. Any disagreement, then or later, and every CRC is computed in software from then on, after one line in the log. The engine is the BLE controller's too, so a run holds the scheduler, leaves alone an engine another task has running, and puts back the registers it borrowed. The Makefiles set NANDLOG_PORT_CRC32.

#define HW_CRC_MIN_BYTES                            64          // shorter runs cost the software less than the engine's setup
#define HW_CRC_POLL_LIMIT                           1000000     // ENABLE polls before a run is given up as hung

typedef enum { HW_CRC_UNTESTED, HW_CRC_IN_USE, HW_CRC_REFUSED } hw_crc_state_t;
typedef enum { ENGINE_DONE, ENGINE_BUSY, ENGINE_FAILED } engine_run_t;

extern void (* const g_am_pfnVectors[])(void);

static hw_crc_state_t hw_crc_state = HW_CRC_UNTESTED;
static uint32_t engine_misses;              // runs the engine was asked for and did not do

static void refuse_engine(const char *why)
{
   hw_crc_state = HW_CRC_REFUSED;
   nandlog_port_log("WARNING: The CRC-32 engine %s; nandlog's CRCs are computed in software from now on\n", why);
}

static engine_run_t engine_run(uint32_t *crc, const uint8_t *words, uint32_t length)
{
   // One run of the engine over 'length' bytes at 'words', both multiples of four, going on from the zlib-style value
   // '*crc', which it replaces only if the run completed
   const bool scheduling = (xTaskGetSchedulerState() == taskSCHEDULER_RUNNING);
   if (scheduling)
      vTaskSuspendAll();
   engine_run_t run = ENGINE_BUSY;
   if (!SECURITY->CTRL_b.ENABLE)
   {
      const uint32_t result_was = SECURITY->RESULT, address_was = SECURITY->SRCADDR, length_was = SECURITY->LEN;
      const uint32_t function_was = SECURITY->CTRL_b.FUNCTION;
      SECURITY->RESULT = __RBIT(~*crc);        // the seed, which the engine takes bit-reversed
      SECURITY->SRCADDR = (uint32_t)words;
      SECURITY->LEN = length;
      SECURITY->CTRL_b.FUNCTION = SECURITY_CTRL_FUNCTION_CRC32;
      if (((uint32_t)words + length) >= (SRAM_BASEADDR + TCM_MAX_SIZE))
         am_hal_sysctrl_bus_write_flush();      // as the HAL does: writes outside the TCM must land before the engine reads
      SECURITY->CTRL_b.ENABLE = 1;
      uint32_t polls = 0;
      while (SECURITY->CTRL_b.ENABLE && (++polls < HW_CRC_POLL_LIMIT));
      if (SECURITY->CTRL_b.ENABLE)
         run = ENGINE_FAILED;                   // still running: its registers stay as they are
      else
      {
         run = SECURITY->CTRL_b.CRCERROR ? ENGINE_FAILED : ENGINE_DONE;
         if (run == ENGINE_DONE)
            *crc = SECURITY->RESULT;            // the finished CRC
         SECURITY->RESULT = __RBIT(~result_was); // RESULT reads as it did before
         SECURITY->SRCADDR = address_was;
         SECURITY->LEN = length_was;
         SECURITY->CTRL_b.FUNCTION = function_was;
      }
   }
   if (scheduling)
      xTaskResumeAll();
   return run;
}

static uint32_t crc_by_engine(uint32_t crc, const uint8_t *bytes, uint32_t length)
{
   // The software to the first word boundary, the engine for the whole words after it, and the software for the rest.
   // A run the engine does not do goes to the software too; one it starts and does not finish refuses it for good
   uint32_t head = (uint32_t)(-(uintptr_t)bytes & 3);
   if (head > length)
      head = length;
   crc = nandlog_crc32_software(crc, bytes, head);
   bytes += head;
   length -= head;
   const uint32_t words = length & ~3u;
   if (words)
   {
      const engine_run_t run = engine_run(&crc, bytes, words);
      if (run != ENGINE_DONE)
      {
         ++engine_misses;
         if ((run == ENGINE_FAILED) && (hw_crc_state == HW_CRC_IN_USE))
            refuse_engine("did not complete a run");
         crc = nandlog_crc32_software(crc, bytes, words);
      }
   }
   return nandlog_crc32_software(crc, bytes + words, length - words);
}

static const char *engine_disagreement(void)
{
   // The engine's CRC of "12345678" from the HAL's seed; then the engine's whole path, the software's head and tail
   // around it, against the software alone: "123456789" at every alignment, 4,064 bytes of the program image in
   // MRAM whole and continued from a split at an odd offset, and runs in RAM at every alignment, whole and split.
   // Every one of them must have been the engine's. NULL if all agree, else what disagreed
   static const uint8_t check[] = "123456789";
   const uint8_t *image = (const uint8_t*)g_am_pfnVectors;
   uint32_t ram[68], value = 0;
   memcpy(ram, check, 8);
   const engine_run_t first = engine_run(&value, (const uint8_t*)ram, 8);
   if (first == ENGINE_BUSY)
      return "was running for another driver when it was to be checked";
   if (first != ENGINE_DONE)
      return "did not complete its first run";
   if (value != 0x9AE0DAAFu)
      return "gives the wrong CRC of \"12345678\"";
   const uint32_t misses = engine_misses;
   for (uint32_t align = 0; align < 4; ++align)
   {
      memcpy((uint8_t*)ram + align, check, 9);
      if (crc_by_engine(0, (const uint8_t*)ram + align, 9) != 0xCBF43926u)
         return "disagrees on \"123456789\"";
   }
   const uint32_t whole = nandlog_crc32_software(0, image, 4064);
   if ((crc_by_engine(0, image, 4064) != whole) || (crc_by_engine(crc_by_engine(0, image, 1001), image + 1001, 4064 - 1001) != whole))
      return "disagrees on 4,064 bytes of MRAM";
   memcpy(ram, image + 512, sizeof(ram));
   for (uint32_t align = 0; align < 4; ++align)
   {
      const uint8_t *bytes = (const uint8_t*)ram + align;
      const uint32_t length = sizeof(ram) - 4, ram_whole = nandlog_crc32_software(0, bytes, length);
      if ((crc_by_engine(0, bytes, length) != ram_whole) || (crc_by_engine(crc_by_engine(0, bytes, 101), bytes + 101, length - 101) != ram_whole))
         return "disagrees on a run in RAM";
   }
   return (engine_misses == misses) ? NULL : "left runs to the software during its check";
}

uint32_t nandlog_port_crc32(uint32_t crc, const void *data, uint32_t length)
{
   if ((hw_crc_state != HW_CRC_IN_USE) || (length < HW_CRC_MIN_BYTES) || xPortIsInsideInterrupt())
      return nandlog_crc32_software(crc, data, length);
   return crc_by_engine(crc, (const uint8_t*)data, length);
}

bool nandlog_port_crc32_hardware(void)
{
   return hw_crc_state == HW_CRC_IN_USE;
}

bool nandlog_port_init(void)
{
   ...                                  /* the SPI bring-up above */

#if NANDLOG_PORT_CRC32
   // Once a boot, before the log computes its first CRC: the engine is used only if it agrees on every vector
   if (hw_crc_state == HW_CRC_UNTESTED)
   {
      const char *disagreement = engine_disagreement();
      if (disagreement)
         refuse_engine(disagreement);
      else
      {
         hw_crc_state = HW_CRC_IN_USE;
         nandlog_port_log("INFO: The CRC-32 engine agrees with the software; nandlog's CRCs of %u bytes or more use it\n",
                          (uint32_t)HW_CRC_MIN_BYTES);
      }
   }
#endif
   return true;
}

Checking your port

  1. nandlog_probe() should return true. If it does not, the part is not answering its identity command — check wiring, clock polarity and chip-select.
  2. nandlog_init() should return true, and a first boot will scan every block for factory bad-block markers.
  3. Begin an epoch inside a session. Until one is begun, nandlog_store_record() returns NANDLOG_ERR_NO_EPOCH.
  4. Store a few records, nandlog_flush(true), and read them back. If writes appear to succeed but nothing reads back, check write-protect polarity.
  5. Run the three on-device tests, which exercise the parts of the chip interface a host simulator cannot.
  6. With NANDLOG_PORT_CRC32, check that your hook's verdict on its engine is the one you expect, and that nandlog_crc32() gives 0xCBF43926 for "123456789". The on-device benchmark reports both (BENCH_INFO crc_hook, crc_vectors_ok) and times the hook against the software.
