Chip Drivers

One .c file per part. Fifteen functions, two of them one line each for most parts.

Two drivers are supplied and each is complete on its own — nandlog_chip_common.h holds no command codes, no register numbers and no bit patterns, and there is no shared implementation beneath it. Copy whichever is closer to your part and work from the datasheet.

1. Declare the geometry

Six macros, then the common header. Geometry lives in the driver and nowhere else — not in a board header, not in the configuration file.

/* chips/nandlog_chip_MYPART.c */

#define NANDLOG_CHIP_NAME                    "MYPART"
#define NANDLOG_CHIP_PAGE_SIZE_BYTES         4096   /* main array, excluding spare  */
#define NANDLOG_CHIP_SPARE_SIZE_BYTES        256    /* spare/ECC bytes that follow  */
#define NANDLOG_CHIP_PAGES_PER_BLOCK         64     /* MUST be a power of two       */
#define NANDLOG_CHIP_BLOCK_COUNT             4096
#define NANDLOG_CHIP_RESERVED_BLOCKS         16     /* table blocks, test scratch   */

#include "nandlog_chip_common.h"

The common header checks the set is complete, asserts the page fits NANDLOG_MAX_PAGE_SIZE_BYTES, and derives the addressing that follows. A driver's busy-wait polls the status register at most NANDLOG_BUSY_TIMEOUT_POLLS times, NANDLOG_BUSY_POLL_INTERVAL_US apart, both from nandlog_conf.h: a count, since the port has no clock.

DerivedValue
NANDLOG_CHIP_PAGE_COUNTpages in the whole array
NANDLOG_CHIP_PAGE_WITH_SPARE_SIZE_BYTESpage + spare
NANDLOG_CHIP_BLOCK_MASKmask a page address to its block
NANDLOG_CHIP_RESERVED_BASE_PAGEfirst page of the reserve
NANDLOG_CHIP_GEOMETRY_INITIALIZERfills a nandlog_geometry_t

How many blocks to reserve depends on how the part handles bad blocks. A driver that keeps its own table and lets the log step over bad blocks where they lie needs no spare blocks: the reserve is only where the table lives, plus scratch for the on-device tests. The Alliance driver reserves 16 of 4096 — its table in the first eight, the tests' scratch in the top eight — and bad blocks, up to the datasheet's 80, cost the log region capacity wherever they fall. A part that remaps in hardware needs its spare pool reserved: the Winbond driver keeps 40 of 1024 for the part to remap into. If the reserve itself fails, a driver that keeps its own table can ask the log for blocks of the region instead (section 3).

2. Implement fifteen functions

Power contract. Every function below that touches the bus may assume the port is awake and the part is out of its low-power state. The log core guarantees that — it wakes both around each operation and puts them back afterwards, or holds them awake for the length of a session.

The corollary matters when you write a bench test for your driver: nandlog_init() deliberately leaves both asleep when it returns, so code that calls these functions directly must open a session first. On a peripheral that is merely unclocked rather than absent, the failure is a bus fault, not an error return. nandlog_chip_geometry() and nandlog_chip_is_bad_block() are the exceptions: both answer from RAM.

Identity and setup

const nandlog_geometry_t *nandlog_chip_geometry(void);

Return the geometry. Valid at any time, including before nandlog_chip_init(), because these are properties of the silicon rather than of its state.

const nandlog_geometry_t *nandlog_chip_geometry(void)
{
   static const nandlog_geometry_t geometry = NANDLOG_CHIP_GEOMETRY_INITIALIZER;
   return &geometry;
}
bool nandlog_chip_probe(void);

Confirm the part is present and answering, typically by reading its device ID and retrying for a bounded time. Safe to call before nandlog_chip_init().

void nandlog_chip_init(void);

Configure the part's status registers, then load the persisted bad-block table or, on a first boot, build one from the factory markers and persist it. Called once, after a successful probe.

void nandlog_chip_low_power(bool sleep);

Enter or leave the part's lowest-power state. May be empty if the part has no deep-power-down command worth the wake-up latency.

Data

nandlog_read_result_t nandlog_chip_read_page(uint8_t *buffer, uint32_t page);

Read a whole page with the part's ECC on, and report the part's verdict:

ValueMeaning
NANDLOG_READ_UNCORRECTABLE (0)The part's ECC could not correct the page. The buffer holds raw cells.
NANDLOG_READ_OKNo error, or errors corrected with margin to spare.
NANDLOG_READ_AT_ECC_LIMITCorrected, but only at the limit of the part's ECC: readable, and worth reporting. A page the log has just written that reads back so counts as not written; a copy of the newest metadata slot that reads so at boot is written again elsewhere.

Zero is unreadable, anything else is usable data. Decode your part's status bits from its datasheet, not by analogy. The Alliance part reports ECCS 11b for a page corrected at the ECC maximum, which is readable; the Winbond part uses the same code for an uncorrectable error in a continuous read. Testing one bit for "uncorrectable" is right for the second and wrong for the first. A part with no "at the limit" verdict, like the Winbond one, simply never reports it; the log then never writes a slot again for its wear.

nandlog_read_result_t nandlog_chip_read_page_region(uint8_t *buffer, uint32_t page,
                                                    uint32_t offset, uint32_t length);

Read length bytes starting at offset within the page. Same result.

This one carries the most weight. The log reads far more 32-byte headers than whole pages, and a driver that implements this as "read the whole page and copy a slice" throws away the entire saving. It must issue the part's column address. On a full epoch of a 4 KB-page part that is the difference between 8 MB and 1 GB of bus traffic for a single bounded download.

Reading less than a page is safe on any part with on-die ECC: correction happens when the page is latched into the cache register, so the error status is settled before a byte is clocked out and cannot depend on how much of that register the host then looks at.

static nandlog_read_result_t read_page_region(uint8_t *buffer, uint32_t page, uint32_t column, uint32_t length)
{
   /* 16-bit column address, most significant byte first, then a dummy byte */
   const uint8_t column_address[3] = { (uint8_t)(column >> 8), (uint8_t)column, 0x00 };
   uint8_t page_address[3];
   split_page_address(page, page_address);

   wait_until_not_busy();
   nandlog_port_transfer_write(COMMAND_PAGE_DATA_READ, NULL, 0, page_address, sizeof(page_address));
   const uint8_t status = wait_until_not_busy();      /* the word that ends the wait carries the verdict */
   nandlog_port_transfer_read(COMMAND_READ, column_address, sizeof(column_address), buffer, length);
   switch (status & STATUS_ECC_MASK)
   {
      case STATUS_ECC_UNCORRECTABLE: return NANDLOG_READ_UNCORRECTABLE;
      case STATUS_ECC_AT_LIMIT:      return NANDLOG_READ_AT_ECC_LIMIT;
      default:                       return NANDLOG_READ_OK;
   }
}
bool nandlog_chip_page_is_blank(uint32_t page);

Whether every bit of the page, main area and spare, reads erased. This is how the log tells the write head from a page a power cut tore, and it programs nothing that has not either been erased by it or passed this test.

Read with the part's ECC bypassed where the part allows it — turn ECC off in its configuration register, read the whole page and spare, turn it back on. An ECC engine's handling of an erased page can correct a few stray programmed bits to 0xFF, which hides exactly the lightly programmed page this exists to find. Count every bit: a false "not blank" costs one page, a false "blank" costs a second program on a part that permits one, so err towards the former. nandlog_chip.h provides nandlog_bytes_erased(data, length) for the scan; it goes 16 bytes a step, where a byte-at-a-time loop over a 4,352-byte page and spare cost about 360 µs on a 96 MHz Cortex-M4.

bool nandlog_chip_write_page(const uint8_t *data, uint32_t page);

Program a whole page with one PROGRAM EXECUTE. Returns false if the part reported a program failure. Never repeat a program that failed: the page may now hold a partial program, and a part with one program per page (NOP = 1, as both supplied parts are) does not allow a second. The log relocates the block instead. Open and close write protection for yourself.

Always start PROGRAM LOAD at column 0. A PROGRAM LOAD may not clear the cache register before its start column. On the Alliance part it resets the register to FFh only from the column it names to the end of the spare area. Bytes before that column keep whatever the last page read or load left there, and PROGRAM EXECUTE programs them too. On silicon, a one-byte load at the spare area's column, issued after a page of zeros had been read, wrote 4,096 zeros into the main area. So never load at a non-zero column, with 02h or with a random-data load. To change a few bytes of a page, such as a bad-block mark in the spare area, load the whole page and spare area from column 0, FFh everywhere else. FFh programs nothing. Both supplied drivers have one function that issues PROGRAM LOAD, and it always loads the whole of what it writes, in one 02h from column 0: a page, or a page and its spare area for a mark, from a buffer that size. Neither uses PROGRAM LOAD RANDOM DATA (84h), which the Alliance datasheet allows only in an internal data move, after a page read of the source; the OTP area takes only page reads and page programs, and a mark has no page it is sure to find erased to move from. The simulator models the Alliance behaviour, so a load from any other column programs stale bytes there as well, and it refuses an 84h outside an internal data move.

bool nandlog_chip_erase_block(uint32_t page);

Erase the block containing page, attempting it up to NANDLOG_BLOCK_ERRORS_BEFORE_REMOVAL times — unlike a program, an erase can be repeated harmlessly. False means the part reported an erase failure every time.

nandlog_copy_result_t nandlog_chip_copy_page(uint32_t source_page, uint32_t destination_page);

Relocate one page to another inside the chip. Most SPI NAND can latch a page into its own cache register and program it straight back out to a different address, so a page that is only being moved never crosses the bus — on a 4 KB part that is 8 KB of traffic saved per relocated page.

Return one of:

ValueMeaning
NANDLOG_COPY_OKThe part did it.
NANDLOG_COPY_FAILEDThe part tried and reported a program failure, so the destination block is suspect.
NANDLOG_COPY_UNSUPPORTEDNo such command. The caller falls back to a read and a write.

A part with no internal data-move command expands a macro instead of writing this out:

NANDLOG_CHIP_NO_INTERNAL_PAGE_COPY

The implementation is a page read followed by one program execute, with no program data load between them — that is the whole point:

wait_until_not_busy();
nandlog_port_transfer_write(COMMAND_PAGE_DATA_READ, NULL, 0, source_address, 3);
wait_until_not_busy();
nandlog_port_transfer_write(COMMAND_WRITE_ENABLE, NULL, 0, NULL, 0);
nandlog_port_transfer_write(COMMAND_PROGRAM_EXECUTE, NULL, 0, destination_address, 3);
wait_until_not_busy();

The log reads the source page's header first and asks for a copy only of a page it can read as the epoch's page at that position. An unreadable page goes over as a tombstone instead — a valid header carrying its sequence number — because a copy of whatever its cells hold could come out erased-looking, and inside the epoch that is where the write-head search would put the head. Every copy is checked by reading its header back.

Bad blocks

bool nandlog_chip_is_bad_block(uint32_t page);

Whether the block containing page is known bad.

This must not touch flash. The log calls it for every block once at boot, to build its own sorted list of the log region's retired blocks, and for the metadata ring thereafter. Answer from a table in RAM, built during nandlog_chip_init(). That boot pass asks about every block in order, so make in-order questions cheap. A search of the whole table for each block costs about 11 ms of a boot with 11 entries at 96 MHz; the Alliance driver keeps the run of blocks around the last one asked about that hold no entry, and so searches once per entry instead.

bool nandlog_chip_mark_bad_block(uint32_t page);

Retire the block, persistently and atomically, and return whether that is now so. The log lays its page positions out over the blocks this driver calls good, so a retirement must survive a power cut at any instant either completely or not at all, and must not show in nandlog_chip_is_bad_block() until it would. A table forgotten, or rewritten in place and cut half-way, re-admits retired blocks into the middle of the epoch. Make this idempotent too — retiring a block that is already retired must not consume a second table slot or a second spare block.

uint32_t nandlog_chip_table_blocks_wanted(uint32_t *lowest_page);

How many blocks of the log region the driver's bad-block table needs because it has run out of places of its own, as a run starting on a multiple of that many blocks, and in *lowest_page the lowest page the run may start at. Zero if none, which is every boot of a healthy part and always for a part that keeps its table in hardware. RAM only. The log asks once a boot, once it knows where the current epoch lies and before it writes anything, and again when a block it is retiring cannot be marked, before it tries the mark once more.

bool nandlog_chip_table_take_blocks(uint32_t first_page);

Take the run of blocks starting at first_page for the table and retire them, all at once: true once the table is on the part there and names every block of the run, which nandlog_chip_is_bad_block() then reports; false with none of them retired. The blocks hold nothing a read could serve and no position of the current epoch — the log has checked — and are the highest such run below the reserve that fits. A driver that never asks returns false.

bool nandlog_chip_reset_bad_blocks(void);

Recovery utility. Discard the persisted table so it is rebuilt on the next boot. Return whether the table was verified gone afterwards, rather than assuming the erase took. Leave alone every block that carries a bad-block marker — erasing one would erase its marker — and keep the table in RAM until the reboot, because the log may carry on logging, and retiring, in the same boot. Return false, saying why through nandlog_port_log(), and discard nothing, if a rebuild would forget a retired block — the Alliance driver programs every entry's mark once more and requires each to read exactly 00h before it erases anything — or if the part remaps in hardware and cannot forget.

The supplied drivers take opposite approaches, which is the point of putting this behind the chip seam.

The software table is written like a log of its own: a new version never overwrites the one it replaces, a page that will not take a program ends the use of its block, and a block is erased for reuse only while another holds the newest version. Every version goes to a pair of pages, so one page that becomes unreadable costs nothing. A version that does not read in both copies may be one a cut tore, which can read valid on one boot and not the next; a boot that finds one writes the table it loaded again, numbered past anything the torn version could claim, in a block of its own, before the log lays out a position over it. A block whose versions all fail to read gives way to the block before it, whose newest version is the one the torn block was entered from. The two copies share a block that every boot reads, about ten pages of it, and that a boot which finds the table settled never writes; so whatever wears it — read disturb above all — wears both together. A boot that reads either copy of the newest version only at the limit of the part's ECC loads the table from it and writes the same entries again the way it writes a torn version, into a fresh block; and no version counts as written whose read-back the part corrects only at the limit, so a page stuck there costs one boot one version, not every boot. A driver of your own that keeps paired copies of anything in the array should do the same. The same wear can program one bit of the block's spare-area mark, which is outside the ECC: a block of the reserve whose mark reads one programmed bit, holding a version newer than the one loaded without it, which that version does not name, is read as unmarked, and its version is loaded and written again into a fresh block. No mark the driver goes by reads so, and only a cut leaves one so, which then reads as a cut that left none can. The table pages carry the magic 'BBT3', a tag whose digit is no version. The table is the authority — finding the spare-area marks would cost a read of every block at every boot — and the marks are what it is rebuilt from in the one case nothing else is left. A mark goes on after the version that names the block, so a cut can fall between them; every boot therefore reads the marker of each block the table names, one ECC-off read apiece, and programs again any that does not read exactly 00h. A marker is read with ECC off because the cells are what count: a page the ECC engine cannot correct is not a mark. A table holding more entries than the datasheet allows bad blocks is reported and kept, never discarded.

When the reserve cannot hold the table

One board's reserve was found dead: every block reading 00h, main and spare, and refusing every program and erase. With the table nowhere, every boot rebuilt it from the marks, and the first block to fail in the log region stopped the log, its retirement having nowhere to go. The Alliance driver answers in two ways, with the on-flash format unchanged.

  • Below the reserve. When no block of the reserve can be entered, or the marks stand in for the table, the driver asks for two blocks (nandlog_chip_table_blocks_wanted()). At the next boot the log gives it the highest aligned pair below the reserve that lies outside the current epoch's positions, is not the head's block, and holds no page with a valid header of any epoch — on a part in service, blocks erased ahead of the head or never written; an earlier epoch's pages are never taken. Before choosing, it erases any such block whose first page is programmed but not with a page of the log — what a cut can leave of a move begun there. The driver erases both blocks and writes the table, naming both, into the lower one, which the log would reach first; only then does it let the old table go — every reserve block that may hold a version is marked, its newest version's last — and it writes a second version, which tells later boots the move finished. The two blocks are retired like any failed block, so positions are laid out past them and the ring's retired count and fingerprint agree, and the table rotates over them as it rotates over the reserve's eight. They are the one kind of entry that carries no mark, since a mark would hide the versions in them. A boot reads the reserve's candidates first, and only if none of them yields a version reads one header a block down to NANDLOG_CHIP_TABLE_SEARCH_BLOCKS from the top of the array (the reserve and the 48 blocks under it, by default), two for a block whose first page reads erased: about 13 to 26 ms. The newest version found decides the pair; paired copies, the settled checks and writing a version again in the pair's other block work as in the reserve.
  • Degraded mode. With no pair to be had, the spare-area marks become the record. First every block the table names is marked once more and must read exactly 00h, and every block that may hold a version is marked, the newest version's last, so no boot can load one. A retirement is then committed by its block's own mark, programmed with the column-0 load and ECC off, after the log has moved the block's pages one block ahead, and read back exactly 00h. A cut before the mark leaves the block good and its failed page recorded in the ring, so the next boot moves it again; a mark a cut tore reads as none, the same, or as a mark — and the copies are already where its positions fall. Every boot of degraded mode rebuilds the table from one raw read of every block's mark, programs every mark once more (a torn mark can read 00h once and FFh later), and looks for a pair again. The rebuild takes any byte but FFh for a mark, as the datasheet has software do for the factory's: a mark a cut left with a bit or two programmed, or with cells that read differently from one latch to the next, then reads as a mark at every boot, which is what keeps a retirement committed by its mark the same at every boot. A rule that let a stray bit go would read such marks as none at one boot and as marks at another; the simulator's exhaustive check shows that losing pages. The price is that the mark bytes are outside the part's ECC, so a stray programmed bit in a good block's byte retires the block, here and in the rebuild after the recovery utility: capacity lost, or, for a block holding part of the current epoch, that block's pages out of reach and the epoch sealed, nothing erased — by its newest slot when that already counts the block in its span, and otherwise by the head search, which then reads pages of the epoch below their own positions, something the log's own retirements never leave. Only a stray bit in the block the write head is in shows nothing: its pages are out of reach and their sequence numbers are used again.

Neither costs a healthy part a read. When neither can record a retirement — the table's blocks failing and the block refusing even the mark that would stand in, or a retired block that will not take its mark, so the marks cannot stand in at all — the log gives the table a pair in the middle of the call that needed it, under the boot's rules, and the retirement goes through the table there; besides those rules, the block being retired and the block a relocation of the head is copying into are never given. The call does at most one debris pass, tries at most NANDLOG_PAGE_PLACEMENT_ATTEMPTS pairs and writes the ring's slot once, as any retirement does. Only with no pair anywhere does the log stop, reported exactly as before. Degraded mode also erases, before it lets go of the table, any block below the reserve that carries the table's magic but that the table does not name, so a move a cut stopped can never be loaded later.

The core keeps the driver honest the other way. Every metadata slot records how many blocks were retired and which of the epoch's own blocks were, and a boot whose table lays the epoch out differently — fewer retired blocks, or others among the epoch's — seals the epoch rather than shift positions under pages already written. The one retirement it excuses, the failed head's block whose relocation the slot recorded, it excuses only with the write head at or past the failed page's position: a mark a cut tore can read as none at one boot, which relocates the block again and may itself be cut part-way through the copies, and as a mark at the next, which would otherwise lay the epoch out without the pages left behind. The seal's slot keeps that record rather than the table's, so every later boot finds the same disagreement, and the next epoch begins past every block still holding one of the epoch's pages.

The hardware LUT holds twenty entries, and the first boot spends one on every factory-bad block it finds, so a part that ships with many leaves that many fewer for blocks that fail in service — possibly none. Once it is full, a failing block cannot be retired and the log stops taking pages (NANDLOG_ERR_UNWRITABLE) rather than write into it; records it had accepted but not yet committed are counted lost. Nothing in the driver can change that; it is the silicon's capacity. That an entry is written whole or not at all if power fails during the write is the part's to guarantee; the simulator assumes it, and nothing here has checked it on silicon.

4. Test it

Point the host simulator at your driver by adding a configuration to sim/Makefile (the Winbond one is the model to copy), then:

cd sim && make

The simulator emulates a NAND part at the SPI command level, so your driver runs on it unmodified — addressing, status-register handshakes, busy-waiting and bad-block bookkeeping are all exercised. It builds the emulated part from whatever geometry your driver reports, so the two cannot disagree, and the regression tests and make campaign hold the driver to the same contract as the supplied ones: no repeated programs, a blank test that sees light tears, and a retirement that survives a cut anywhere.

Then run the on-device tests. Those cover what the simulator cannot: whether your column addressing is right on real silicon, whether the internal copy behaves, and what the part's on-die ECC does to the spare area.

A wrong column byte order fails open. It reads 0xFF from the wrong place, the factory bad-block scan concludes every block is good, and nothing is retired. The host simulator cannot catch this, because it decodes the column address the same way your driver encodes it. Run the on-device read test before deploying.
