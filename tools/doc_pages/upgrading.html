Upgrading

What changed in 1.2, and what it costs you.

The on-flash format has not changed. A log written by any 1.x release parses with any other, and there is no migration on the part. What changed is the spelling of the API.

Renamed

WasNowWhy
nandlog_port_spi_read()nandlog_port_transfer_read()The seam is command–address–data, which is not specific to SPI
nandlog_port_spi_write()nandlog_port_transfer_write()
nandlog_store_metadata()nandlog_begin_epoch()Beginning an epoch is the main effect; storing the details is what it does on the way
nandlog_retrieve_metadata()nandlog_retrieve_epoch_details()It returns the caller's details, not the log's metadata
nandlog_enter_maintenance_mode()nandlog_begin_session()It is a scope, not a mode, and nothing is out of service during one
nandlog_exit_maintenance_mode()nandlog_end_session()
NANDLOG_MAX_METADATA_BYTESNANDLOG_MAX_EPOCH_DETAILS_BYTESIt bounds the caller's blob, not the ring

Required additions

WhatWhere
NANDLOG_CHIP_PAGE_COPYnandlog_conf.h must define it. Default 1.
nandlog_chip_read_page_region()Every chip driver. It is nandlog_chip_read_page() over part of a page, and must issue a real column address.
nandlog_chip_copy_page()Every chip driver — or expand NANDLOG_CHIP_NO_INTERNAL_PAGE_COPY instead.

What each kind of file needs

FileWork
Your nandlog_port.cTwo function renames. Nothing else.
Your chip driver, if you wrote oneTwo new functions, plus the port renames inside it.
Your nandlog_conf.hOne new macro, one renamed macro.
Your applicationFour API renames.

A mechanical rename handles all of it:

grep -rl 'nandlog_port_spi_\|nandlog_store_metadata\|nandlog_retrieve_metadata\|maintenance_mode\|NANDLOG_MAX_METADATA_BYTES' . \
  | xargs sed -i '' \
      -e 's/nandlog_port_spi_read/nandlog_port_transfer_read/g' \
      -e 's/nandlog_port_spi_write/nandlog_port_transfer_write/g' \
      -e 's/nandlog_store_metadata/nandlog_begin_epoch/g' \
      -e 's/nandlog_retrieve_metadata/nandlog_retrieve_epoch_details/g' \
      -e 's/nandlog_enter_maintenance_mode/nandlog_begin_session/g' \
      -e 's/nandlog_exit_maintenance_mode/nandlog_end_session/g' \
      -e 's/NANDLOG_MAX_METADATA_BYTES/NANDLOG_MAX_EPOCH_DETAILS_BYTES/g'

New

  • Reading an earlier epoch — nandlog_epoch_count(), nandlog_epoch_info(), nandlog_select_epoch(), nandlog_select_current_epoch().
  • Chip-internal page relocation, which keeps a relocated page off the bus entirely.
  • Partial page reads throughout the library, cutting bus traffic on boot and on a bounded download by roughly two orders of magnitude. See Performance.
  • Version macros: NANDLOG_VERSION_MAJOR, NANDLOG_VERSION_MINOR, NANDLOG_VERSION_AT_LEAST().

Behaviour changes

  • NANDLOG_HAS_HARDWARE no longer consults any application-specific macro. A build that wants the no-op stand-ins must define it as 0 explicitly.
  • Retiring a block is idempotent in both supplied drivers.
  • An erase will never be issued to a block the driver already considers bad.

Guarding against the next change

#endif
