API Reference

Everything in nandlog.h. Include that one header.

Every public function takes an internal lock for its whole duration, so a caller never holds one and calls never nest — the small accessors included. All of them are safe to call from any thread provided your port supplies a real mutex. The one exception is nandlog_data_bytes_per_page(), which reads constants and needs no lock. The lock is one lock: a nandlog_store_record() that only copies into RAM waits behind whatever holds it, and the longest holders are a bounded nandlog_begin_reading() and a nandlog_read_span() with a byte total, each a pass over the epoch — on a full epoch of the Alliance part, minutes (see Performance). A logger that cannot wait that long buffers its records itself while a download is open.

Lifecycle

bool nandlog_probe(void);

Confirm a part is present and answering, without bringing the log up or writing anything. Intended for builds that only test for its presence; nandlog_init() performs the same check for itself.

bool nandlog_init(void);

Bring the log up: open the port, identify the part, load its bad-block table, recover the current epoch from the metadata ring, and locate the write head within it. Safe to call more than once.

Returns false if the port could not be opened or the part did not answer. No other call should be made in that case.

void nandlog_deinit(void);

Release the port. The log can be brought back up with nandlog_init(). Anything still buffered in RAM is dropped, exactly as a power cut would drop it, so flush first.

void nandlog_disable(bool disable);

Stop or resume accepting records. A disabled log refuses what it is given (NANDLOG_ERR_DISABLED) rather than buffering it, and still serves reads; what it accepted before can still be committed with nandlog_flush(), which while the log is disabled commits and does nothing else. Nothing is disabled by nandlog_init(). This does not override the log's own refusal after the part stopped retaining pages, which lasts until a reboot or a new epoch, nor a sealed epoch's, which lasts until a new epoch.

uint32_t nandlog_data_bytes_per_page(void);

Payload bytes a page can carry on the fitted part: the page size less the header the log writes into it. Answered from the chip driver, so it is correct before nandlog_init() has run.

Sessions

A session holds the part powered across a run of operations instead of waking and sleeping it around each one. Epoch operations and reads require one; ordinary logging does not. Sessions do not nest.

void nandlog_begin_session(void);
void nandlog_end_session(void);

Open and close a session. Ending one implies nandlog_end_reading() and returns the read view to the current epoch.

Epochs

An epoch is one generation of the log: a numbered run with its own start page and its own sequence numbering from zero. Reads cover one epoch at a time.

bool nandlog_begin_epoch(const void *blob, uint16_t length);

Begin a new epoch, described by an opaque caller-defined blob of at most NANDLOG_MAX_EPOCH_DETAILS_BYTES. The log neither reads nor interprets the blob. An earlier epoch written by a build that allowed more keeps its longer details, and reports their length in nandlog_epoch_info(); nandlog_retrieve_epoch_details() truncates them to the length it is given. Everything logged previously stays on the part but stops being reachable through nandlog_begin_reading(), since reads cover the current epoch unless told otherwise. Records still buffered for the old epoch are committed to it first.

The new epoch begins in the old one's last block if the old one has nothing in it, else in the next good block; on a full region it begins in the full epoch's own first block. Its slot in the metadata ring is the commit point: until it is on the part the old epoch is current and untouched. A new epoch is also the way out of a sealed one (NANDLOG_ERR_SEALED) and of a log that stopped taking pages.

Requires a session, with no read open. Returns false if there is no session, if a read is open, if the blob is too large, if the buffered records could not be committed, or if no slot in the metadata ring would take it. Until the first epoch is begun on a part, records are refused.

void nandlog_retrieve_epoch_details(void *blob, uint16_t length);

Copy back the details of whichever epoch is selected, truncated to length. Zero-fills if there are none, so a caller that never stored any reads zeros rather than stale bytes.

Reading an earlier epoch

An earlier epoch is not preserved, only left alone. The write head sweeps forward from where the previous generation stopped and erases each block just before it needs it, so an epoch is eaten from its start as the current one grows. A block of it can also go a little ahead of that: one the window tries to erase and cannot is retired, and a retired block's pages are no longer read, though nothing erased them. What comes back is whatever is left; a page that has been swept over reads as a gap exactly like one that rotted.

uint32_t nandlog_epoch_count(void);

How many epochs the metadata ring still describes, the current one included, capped at NANDLOG_MAX_LISTED_EPOCHS (16). Walks the ring backwards from the current epoch's slot, reading about one header per epoch listed and stopping as soon as it has enough. Nothing is cached between calls.

bool nandlog_epoch_info(uint32_t index, nandlog_epoch_info_t *info);

Describe the index-th epoch, newest first, so index 0 is always the current one. Returns false once the index runs past what the ring describes.

typedef struct
{
   uint32_t epoch;               /* the generation number                        */
   uint32_t created_timestamp;   /* always 0: the log reads no clock; put a time */
                                 /*   in the details blob instead                */
   uint32_t first_page;          /* the page it was begun at; seq 0 is there, or */
                                 /*   in the next good block if that one has    */
                                 /*   since been retired                        */
   uint16_t details_length;      /* bytes of caller-defined details in its slot  */
   bool     is_current;          /* whether this is the epoch being written now  */
   bool     is_sealed;           /* the current epoch takes no more pages       */
   bool     layout_unverified;   /* the bad-block table no longer lays the      */
                                 /*   current epoch out as it was written       */
} nandlog_epoch_info_t;

is_sealed says the current epoch takes no more pages until a new one is begun (NANDLOG_ERR_SEALED). layout_unverified says why, in the one case that matters to a read: the bad-block table no longer lays the epoch's positions out as they were written — both copies of its newest version lost, say — so a read of it goes ahead as best it can, and may miss pages or serve a page a relocation copied twice under its one sequence number. Such a read also logs an error as it opens. The seal's slot keeps the layout the epoch was written by, so the flag stands at every boot until a new epoch is begun, and the epoch begun after it, at whichever boot, starts past every block still holding one of its pages. Both are false for an earlier epoch.

bool nandlog_select_epoch(uint32_t epoch);
void nandlog_select_current_epoch(void);

Point reads at an epoch other than the one being written, and back again. Writing is refused while an earlier epoch is selected, so a download cannot be mistaken for somewhere to put data.

nandlog_select_epoch() requires a session, fails while a read is open, and returns false if no slot in the ring names that epoch. Ending the session also returns to the current epoch.

A read of an earlier epoch ends at the last page it wrote, found by reading the headers of the block before the one its successor began in, from its end back. Every page from another epoch is a gap, never data. A read that yields nothing means the epoch has been overwritten, not that it never existed — compare against nandlog_epoch_info(), which still describes it from the ring.

nandlog_begin_session();

for (uint32_t i = 0; i < nandlog_epoch_count(); ++i)
{
   nandlog_epoch_info_t info;
   if (nandlog_epoch_info(i, &info))
      printf("epoch %u%s\n", info.epoch, info.is_current ? " (current)" : "");
}

if (nandlog_select_epoch(previous))
{
   nandlog_retrieve_epoch_details(&details, sizeof(details));
   nandlog_begin_reading(0, 0);
   /* ... the usual read loop ... */
   nandlog_end_reading();
}

nandlog_end_session();

Writing

nandlog_status_t nandlog_store_record(uint8_t record_type, uint32_t timestamp,
                                      const void *data, uint32_t data_length);

Append one record to the page being assembled in RAM. record_type and data are opaque to the log; the timestamp is only ever compared, never interpreted, so its epoch and units are yours.

A timestamp may be earlier than records already in the page by up to NANDLOG_TIMESTAMP_TOLERANCE_MS — in the units of your timestamps, which are milliseconds only if you made them so — as when one record is stamped when something starts and stored after another writer's record that was stamped later. It is kept exactly as given, and the page's bounds widen to cover it, so a page is not necessarily in time order. A larger backward step means the time base moved, and commits the page first. 0xFFFFFFFF, the header's "no timestamp" value, is a time like any other: the record keeps it, and its page's bounds count it as 0xFFFFFFFE.

Each call adds its record to the page's CRC, so the call that commits the page computes only its header's. Committing a full page happens here, so this call occasionally writes to flash. A call that commits a page never also erases a block, unless the block the write head is entering was never erased ahead of it. Records are never split across pages. With NANDLOG_RECORD_FRAMING on, the record is prefixed with its own data length, costing two bytes.

Returns NANDLOG_OK if the record was stored, and otherwise why it was not:

StatusMeaning
NANDLOG_ERR_NOT_INITIALIZEDnandlog_init() has not succeeded.
NANDLOG_ERR_NO_EPOCHNo epoch has ever been begun on this part.
NANDLOG_ERR_DISABLEDnandlog_disable(true), or the log stopped itself after the part stopped retaining pages.
NANDLOG_ERR_EARLIER_EPOCHAn earlier epoch is selected for reading.
NANDLOG_ERR_READINGA read is open, and storing this record meant committing a page.
NANDLOG_ERR_TOO_LARGEThe record can never fit in a page, whatever its length, up to 232 − 1.
NANDLOG_ERR_FULLEvery page of the log region belongs to the current epoch. Begin a new one.
NANDLOG_ERR_UNWRITABLEA commit this call needed failed: no block would retain the page. The records already buffered for it are lost too, and counted as such.
Either of those two also comes back when the erase-ahead this call carried left what is buffered no block to be committed to: the records already buffered are counted lost, and this one is refused rather than reported stored.
NANDLOG_ERR_SEALEDThe epoch is sealed and takes no more pages until a new one is begun: its list of passed-over positions is nearly full, its newest metadata slot no longer reads with that list whole, or the bad-block table no longer lays its pages out as they were written. The seal is in the epoch's slot, so every later boot refuses too, and calls nandlog_port_unwritable(). Reads go on.
 
nandlog_status_t nandlog_flush(bool write_partial_pages);

Commit what is buffered. A page is written automatically as soon as the next record will not fit, so this is only needed to force out a partial page — a timed flush, or shutdown. Pass false to write only if a whole page has accumulated.

A call that commits nothing is where the log erases the next block ahead of the write head, if one is due, so an idle nandlog_flush(false) is a good place for that work to land — unless the log is disabled, when a flush only commits. Returns the outcome of the commit, NANDLOG_OK if there was nothing to commit, or why it was refused. An erase-ahead that leaves what is buffered nowhere to go — a block that would not erase, and the region full or no block left to take a page — counts those records lost and returns NANDLOG_ERR_FULL or NANDLOG_ERR_UNWRITABLE.

bool nandlog_has_buffered_data(void);

Whether any records are sitting unwritten in RAM.

Reading

void nandlog_begin_reading(uint32_t starting_timestamp, uint32_t ending_timestamp);

Open a read over the selected epoch, bounded by timestamp. Zero for either bound means "from the beginning" and "to the end"; both bounds are resolved here, so nothing downstream has to seek again. Pages are selected by the time bounds their headers advertise — the smallest and the largest timestamp of the page's records, which need not be its first and last: from the first page whose largest reaches the start, to the last page whose smallest is within the end. Both err outward — a little extra data to filter beats dropping data that was asked for — so every page holding a record stamped within the window is selected, and so can be a page whose records straddle the window without falling in it, or the pages between two that bracket it across a backward step of the time base. A window that ends before the first page found for its start — before the first record, or in a gap between two pages' bounds — selects nothing.

Records still buffered for the current epoch are committed first, exactly as nandlog_flush(true) would, so a read serves only what is on the part. That is what makes a sequence number an identity: whatever a read serves under (epoch, sequence number) is what that sequence number holds from then on — or a gap, if the part later loses the page — and is never given to other records, across any number of reboots and power cuts. Records stored while the read is open are buffered for the next one.

A bound is resolved by reading every page header in the epoch, under the library's lock.

Requires a session. While a read is open, committing a page is refused: a commit that fails relocates the head's block and retires it, and an open read keeps its place by physical page. To keep logging through a long download, see below.

void nandlog_end_reading(void);

Close a read, whether or not it ran to completion. Implied by nandlog_end_session().

void nandlog_read_span(uint32_t *num_pages, uint32_t *num_bytes);

Measure the open read: how many pages it will yield, including any that turn out to be unreadable, and how many payload bytes they hold. Either pointer may be NULL. Reports zero for both if no read is open. Pages are counted over the blocks the part holds good, so a retired block in the epoch adds nothing.

The byte total is exact in both directions — it is computed by exactly the checks that serve the pages, so a page with a sound header and a rotted payload, or a page of another epoch, is neither counted nor delivered. A host sizing a receive buffer depends on that. It is exact on a part that reads each page the same way twice; a page a power cut left with cells that read differently from one read to the next can pass its checks in one pass and not in the other.

The byte total costs a read of every page in the span, doubling the flash traffic of a download. Pass NULL unless the figure is needed exactly; the page count is arithmetic.

uint32_t nandlog_retrieve_next_page(uint8_t *buffer, nandlog_page_header_t *header);

Take the next page of the open read, returning its payload length. buffer needs room for NANDLOG_MAX_DATA_BYTES_PER_PAGE bytes, and nothing past the payload is written to it. Pass NULL for header to ignore the framing metadata; its magic is the page's own record format, which differs from this build's only if NANDLOG_RECORD_FRAMING changed during the epoch. The read closes itself after its last page.

Zero means that page was unreadable, which is not the end of the read. A page whose header could not be read comes back with seq set to the sequence number it must have carried, so the gap is still identifiable. So does a tombstone: the record a relocation leaves of a page that was already unreadable when its block failed.

uint32_t nandlog_retrieve_page_by_seq(uint32_t seq, uint8_t *buffer,
                                     nandlog_page_header_t *header);

Fetch one page of the selected epoch — the current one unless an earlier one is selected — by its sequence number, so a host can re-request what it lost. Returns zero, with the header describing the gap, if that page cannot be produced. In the current epoch a sequence number is a position, so this is one page read; in an earlier one it falls back to a binary search if a block retired since has shifted positions. No read need be open, so a host can ask after a read has run to its end. What comes back is what any read served under that sequence number, or a gap.

uint32_t nandlog_read_recent_page(uint32_t pages_back, uint8_t *buffer,
                                  nandlog_page_header_t *header, bool *end_of_epoch);

Walk backwards from the write head, newest page first, independently of any open read and without needing a session. Zero means that page could not be read, which is not the end of the log; end_of_epoch is the signal to stop, and is set on the epoch's first page whether or not it could be read. buffer is sized as above, and may be NULL.

bool nandlog_framed_next_record(const uint8_t *payload, uint32_t length, uint32_t *offset,
                                const uint8_t **record, uint32_t *record_bytes);

Step through the records of a payload belonging to a page that announced NANDLOG_PAGE_MAGIC_FRAMED. Initialise *offset to zero and call until it returns false. *record points at [type:1][timestamp:4][data].

uint32_t nandlog_crc32(uint32_t crc, const void *data, uint32_t length);

The CRC-32 the log writes and checks, continued over length more bytes exactly as Python's zlib.crc32(data, crc) continues one: 0 begins a value, and the value returned for the bytes so far goes on from them. A served page's payload_crc is nandlog_crc32(0, buffer, length). It is nandlog_port_crc32() in a build that sets NANDLOG_PORT_CRC32, and the library's own software otherwise, which needs neither nandlog_init() nor the library's lock.

Logging through a long download

While a read is open, a record that would commit a page is refused (NANDLOG_ERR_READING), so a download held open across a slow link stops logging once a page's worth of records is buffered. To go on logging, open the read only to take its span — the first page's sequence number and the page count — close it, and fetch the rest by sequence number, which needs no open read and finds each page afresh, a relocation of the head's block included:

uint32_t first = 0, count = 0;
nandlog_page_header_t header;

nandlog_begin_session();
nandlog_begin_reading(start_ms, end_ms);       /* commits what is buffered, and resolves the window */
nandlog_read_span(&count, NULL);
if (count)
{
   uint32_t length = nandlog_retrieve_next_page(page, &header);
   first = header.seq;                         /* a gap carries its sequence number too: send it */
}
nandlog_end_reading();
nandlog_end_session();

for (uint32_t seq = first + 1; seq < (first + count); ++seq)
{
   uint32_t length = nandlog_retrieve_page_by_seq(seq, page, &header);
   /* zero is a gap, header.seq says which; records stored between calls commit as usual */
}

The window is resolved once, by the short read, so nothing is lost there. A gap fetched by sequence number comes back with a bare header — no time bounds or record count of its own, as an open read reports when a page's header survives but its payload does not — and an exact byte total has to be taken with nandlog_read_span() before the read is closed. Each fetch outside a session powers the part up and down; hold a session around the loop to avoid that, which logging does not mind. This is for the current epoch: writing stays refused while an earlier one is selected. The regression test N1 in sim/nandlog_sim_regress.c fetches a span this way while every store commits a page and the head's block is relocated and retired.

Retransmission

Sequence numbers are contiguous within an epoch, so a host knows exactly which pages it is missing.

void nandlog_retransmit_clear(void);
uint32_t nandlog_retransmit_add(const uint32_t *seqs, uint32_t count);
uint32_t nandlog_retransmit_count(void);

Accumulate the sequence numbers a host reports missing, across as many calls as it takes. nandlog_retransmit_add() returns the number held; anything beyond NANDLOG_MAX_RETRANSMIT_PAGES (256) is dropped.

uint32_t nandlog_retransmit_total_bytes(void);

Exact total of the payload bytes the requested pages will deliver, for a host sizing a receive buffer — exact as nandlog_read_span()'s is. Costs a read of each requested page. Like nandlog_retrieve_page_by_seq(), the retransmission calls need no open read.

uint32_t nandlog_retrieve_retransmit_page(uint32_t index, uint8_t *buffer,
                                          nandlog_page_header_t *header);

Serve the index-th requested page. An index past the end yields a zero-length page rather than nothing, so the host can tell "still missing" from "never answered".

Diagnostics

uint32_t nandlog_bad_block_count(void);

How many blocks across the metadata ring and the log region are retired, factory-marked and grown alike. Answers from RAM: the figure is recomputed when the log comes up and whenever a block is retired, so reading it is free.

Useful as a health indicator over a part's life. A count that climbs steadily is a part approaching the end of its endurance; a count that jumps is worth investigating.

void nandlog_get_stats(nandlog_stats_t *stats);

Running totals since nandlog_init(), from RAM.

typedef struct
{
   uint32_t records_stored;      /* store_record() calls that returned NANDLOG_OK      */
   uint32_t records_refused;     /* calls that returned anything else                  */
   uint32_t records_lost;        /* stored in RAM, but their page could not be committed */
   uint32_t pages_committed;     /* written and verified by reading back               */
   uint32_t pages_relocated;     /* moved out of a failing block, tombstones included  */
   uint32_t tombstones_written;  /* relocated pages that were already unreadable       */
   uint32_t positions_skipped;   /* sequence numbers the last boot passed over: torn   */
                                 /*   pages (and with NANDLOG_PASS_OVER_HEAD_AT_BOOT  */
                                 /*   the head's page), listed, never programmed again */
   uint32_t blocks_retired;      /* by the log, persistently                           */
   uint32_t reads_at_ecc_limit;  /* reads the part corrected at the limit of its ECC   */
} nandlog_stats_t;

A page the part corrects only at the limit of its ECC is delivered, but the next bit to go will not be corrected, and nothing rewrites a page in place: a part that keeps turning these up is wearing out. The count includes the boot's reads of the newest metadata slot; a copy of it read so is written again elsewhere, at that boot.

Recovery

void nandlog_reset_bad_block_table(void);

Discard the persisted bad-block table so it is rebuilt on the next boot. What this can achieve depends on the part: one that remaps in hardware cannot forget, and keeps its table; the Alliance driver rebuilds from the factory markers and from the markers it writes into every block it retires, so a retirement survives it. Every boot checks that each block the table names carries its marker, reading exactly 00h, and programs again one that does not — a marker a cut left part-way can read as a marker once and as none the next time; the utility programs every one again first, and keeps the table if any block it names then does not read 00h, since a rebuild would forget that block. It never erases a marked block, and erases the block holding the newest table version last, and only once every older one is gone, so neither a cut nor a block that will not erase can leave an older version to be loaded. A table kept below the reserve is in two blocks the log gave up, which must stay retired, so they are marked rather than erased, the newest version's last, which passes over every version in them. The rebuild reads markers with ECC off, so a block whose first page merely reads uncorrectable is not taken for a marked one, and the table in RAM stands until the reboot, so logging may carry on meanwhile. If the rebuilt table still lays the current epoch out differently from what its metadata slot recorded, the epoch is sealed (NANDLOG_ERR_SEALED): begin a new one. The outcome is reported through nandlog_port_log().

Version macros

#define NANDLOG_VERSION_MAJOR    1
#define NANDLOG_VERSION_MINOR    0

#define NANDLOG_VERSION_AT_LEAST(major, minor)   /* ... */

Major changes when something you built against must change — a structure that moves on flash or on the wire, a function that is renamed or whose meaning shifts. Minor changes for additions. NANDLOG_FORMAT_VERSION is separate and versions what a build writes on the part; this is version 1 of both. See On-Flash Format.
