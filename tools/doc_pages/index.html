nandlog

Append-only, power-fail-safe, CRC-validated logging on raw SPI NAND. No flash translation layer, no filesystem, no heap.

nandlog is a C99 library for devices that collect data for weeks and hand it over in one go — a battery-powered sensor, a tag, a logger. It assumes writes are small and frequent, reads are rare and bulk, and power can be lost at any instant without warning.

What it provides

CapabilityDetail
Static allocationAbout 18 kB of RAM on a 4 KB-page part, fixed at compile time. No malloc.
Power-fail safetyA page torn by power loss fails its CRC on the next boot and is reported as a gap, never as data.
Corruption detectionSeparate CRC-32 over each page header and each payload.
Bad-block handlingBlocks that refuse a write or an erase are retired, and pages already in them are relocated.
Fast recoveryThe write head is located in O(log n) page reads after a reboot, without scanning the array.
Bulk offloadTime-bounded reads, a framed wire format with per-page CRCs, and per-page retransmission.
Multiple generationsEpochs, with earlier ones still readable until the write head sweeps over them.
Bounded workEvery search loop has a stated bound, so a failing part cannot stall the calling task indefinitely.

What it does not do

  • Interpret records. A record's contents and length are the application's business; the log stores opaque bytes.
  • Read a clock. Timestamps are supplied by the caller, compared, and never interpreted.
  • Allocate. Everything is static and sized at compile time.
  • Wear-level. The write head sweeps forward and wraps. Anything more would need a mapping table.
  • Random-access update. A page is written once and never revised.

A minimal example

#include "nandlog.h"

if (!nandlog_init())
   return;                        /* no part fitted, or the port would not open */

nandlog_begin_session();
nandlog_begin_epoch(&details, sizeof(details));
nandlog_end_session();

nandlog_store_record(RECORD_SAMPLE, milliseconds, &sample, sizeof(sample));
nandlog_flush(true);

See Getting Started for the complete picture, including reading data back.

Any other part needs a driver, which is one .c file. See Chip Drivers.

Requirements

  • A C99 compiler. Build with -fno-strict-aliasing.
  • A SPI NAND part with a power-of-two number of pages per block.
  • Roughly 18 kB of RAM for a 4 KB-page part, less for a smaller one.
  • No RTOS, heap, or filesystem is required. A mutex is required only if more than one thread calls the library.
